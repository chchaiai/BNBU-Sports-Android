# UI-LOGIN-01｜学生端登录入口页设计规范

> 文档类型：UI/UX 设计规范（纯文字）  
> 页面实现：`LoginScreen.kt`  
> 状态：分析稿，未改动业务逻辑

## 1. 页面目标与结构

页面目标是让学生以最短路径完成正式认证，同时清楚提供课程加入、账号恢复和演示入口。正式认证、课程加入和开发/演示能力必须在视觉上分组，不能视为同一类主操作。

```text
安全区
  学校品牌栏
    校徽 + 学校名称 + “BNBU · STUDENT SPORTS”

  页面说明
    标题：登录 BNBU 体育
    辅助说明：管理体育打卡与成绩进度

  登录卡片
    标题：选择登录方式
    隐私同意区
      复选框 + 隐私政策链接 + “同意后可继续登录”提示
    默认正式登录入口
      手机验证码登录（默认主入口，须由产品确认）
    另一正式登录入口
      邮箱验证码登录
    分隔线 + “其他方式”
      扫码加入课程
      Mock 用户快捷登录（仅演示/调试场景）

  账号恢复入口
    无法使用绑定的手机号或邮箱？

  页脚说明
    一期功能范围说明
```

### 操作顺序

1. 用户确认隐私政策。
2. 用户选择手机号或邮箱完成认证。
3. 需要加入课程但尚未登录的用户，进入扫码流程。
4. 无法使用既有联系方式的用户，进入账号恢复流程。
5. Mock 仅服务于演示或开发用途，不能与正式登录争夺首要注意力。

## 2. 间距体系

采用 4dp 基准，优先使用以下固定档位，避免页面内出现无规律的间距。

| 使用位置 | 建议值 |
|---|---:|
| 图标与文字间距 | 8dp |
| 品牌图标与校名间距 | 12dp |
| 卡片内紧密元素 | 12dp |
| 标题与正文、相邻表单元素 | 16dp |
| 卡片内区块间距 | 20dp 或 24dp |
| 页面主区块间距 | 24dp |
| 页面水平边距 | 20dp；大屏最大内容宽度应受控 |
| 卡片内边距 | 20dp 或 24dp |
| 页面顶部、底部安全区外留白 | 24dp 起，适配系统 Insets |

页面应保持纵向滚动，但在常见小屏首屏中至少完整呈现：品牌栏、页面标题、隐私同意区和一个正式登录按钮。产品说明与一期范围说明不可挤占主登录路径。

## 3. 字号体系

所有文本应优先映射到 Material 3 typography token；禁止在同一页面混用多个手工字号作为标题体系。

| 层级 | 建议样式 | 建议用途 |
|---|---|---|
| 页面主标题 | `headlineLarge`，约 30–32sp | “登录 BNBU 体育” |
| 卡片标题 | `headlineSmall`，约 24sp | “选择登录方式” |
| 正文说明 | `bodyLarge`，约 16sp | 产品简述、隐私前置提示 |
| 按钮文字 | `labelLarge`，约 14sp | 所有按钮文案 |
| 品牌副标题/辅助说明 | `labelMedium` 或 `bodyMedium`，12–14sp | 学校英文副标、账号恢复说明 |
| 页脚 | `bodySmall`，约 12sp | 一期功能范围 |

规则：

- 页面只保留一个主标题；不再额外使用超大“BNBU”作为第二个主标题。
- 主标题最多两行；英语、系统大字体或窄屏下允许自然换行，不应截断。
- 正文使用正常字重；仅标题和主按钮使用 `Medium` / `SemiBold`。不使用大量粗体制造层级。
- 校名可保持单行省略；核心操作、隐私声明和账号恢复文案不可省略。

## 4. 颜色语义

颜色必须表达状态与操作层级，不以“好看”为唯一目的。

| 语义 | 推荐令牌/处理 | 使用范围 |
|---|---|---|
| 主操作 | `primary` + `onPrimary` | 默认正式登录按钮、关键链接焦点 |
| 次操作 | `secondaryContainer` / tonal surface | 邮箱登录、次级选择 |
| 替代流程 | `surface` + `outline` 或低饱和 tonal | 扫码加入课程 |
| 开发/演示 | `surfaceVariant` + `onSurfaceVariant` | Mock 用户入口，需明显降级 |
| 基础正文 | `onSurface` | 标题、正式说明 |
| 辅助内容 | `onSurfaceVariant` | 简述、页脚、说明文字 |
| 禁用状态 | M3 disabled 容器与文字对比度 | 未同意隐私政策前的不可用操作 |
| 错误状态 | `error` + `onErrorContainer` | 验证失败、网络错误、提交失败 |
| 成功状态 | `primaryContainer` / 语义成功色 | 验证码已发送、恢复申请提交成功 |

网格背景必须低对比度，仅保留品牌氛围；卡片、正文和按钮始终优先于背景。

## 5. 圆角规则

沿用 Material 3 shape token，避免同屏出现多个近似但不相同的圆角。

| 元素 | 规则 |
|---|---|
| 登录卡片 | `shapes.medium`，建议 12dp |
| 正式登录按钮 | `shapes.extraLarge`，胶囊形可保留 |
| 次级/替代按钮 | 与对应按钮体系使用相同圆角，不另起规则 |
| 小型状态标签 | `shapes.small` / `extraSmall` |
| Logo 容器 | `shapes.medium`，与卡片圆角呼应 |

卡片圆角和按钮圆角可不同，但同一语义的按钮必须一致；不得为扫码、Mock 单独创造不一致的形状语言。

## 6. 按钮规则

### 正式登录

- 默认认证方式：使用 Filled Button，全宽、最醒目。
- 另一认证方式：使用 Filled Tonal Button 或 Outlined Button，全宽，与主按钮保持相同高度和触达面积。
- 默认主入口为手机号还是邮箱必须由产品确认；确认前不得仅凭视觉偏好改变登录能力或默认路由。

### 替代与辅助操作

- 扫码加入课程：使用次级按钮，置于“其他方式”分组内；它不是常规登录方式。
- Mock 用户：使用弱化按钮或文字入口，并加“演示/调试”语义；生产用户不应将其误认作真实账户入口。
- 账号恢复：使用卡片外的 `TextButton`，保留足够点击区域。

### 禁用、加载与反馈

- 未同意隐私政策时，入口保持不可点击，但在复选框附近明确显示“请先阅读并同意隐私政策”。
- 禁用不是错误态，不能使用错误色。
- 请求中按钮显示加载指示器并防止重复点击；不改变按钮宽度或导致布局跳动。
- 所有可点击目标最小高度为 48dp。

## 7. 卡片规则

- 使用单一登录卡片承载认证与合规操作；卡片内边距 20–24dp。
- 卡片标题只保留“选择登录方式”，不重复“SIGN IN”等无额外信息的眉题。
- 正式认证和“其他方式”之间使用分隔线或清晰的 20–24dp 分组距离。
- 扫码和 Mock 即使仍在卡片中，也必须与认证按钮存在视觉分层。
- 卡片不应包含冗长的产品价值说明、一期范围说明或大量帮助文字。

## 8. 加载、空数据与错误状态

| 状态 | 页面表现 | 对应组件名称 |
|---|---|---|
| 恢复本地会话中 | 全屏品牌加载态，说明“正在恢复登录状态” | `AppRootScreen` + `CircularProgressIndicator` |
| 发送验证码中 | 发送按钮内加载指示器；输入框保持稳定 | `LoadingButton` / `PrimaryActionButton(loading = true)` |
| 60 秒冷却 | 显示剩余时间，禁止再次发送 | `CooldownTextButton` |
| 无缓存且网络不可用 | 可理解的错误说明、重试操作 | `ErrorState` + `TextButton` |
| 有缓存的离线模式 | 非阻塞提示条，清楚说明数据可能非最新 | `OfflineBanner` / `SnackbarHost` |
| 验证码/账号错误 | 字段附近明确错误文案，不仅显示 Toast | `SupportingText` + `error` 色 |
| 验证码已发送 | 输入区进入第二步，显示发送目标的脱敏提示 | `StatusBanner` / `SupportingText` |
| 恢复申请已提交 | 成功确认页或卡片状态，说明后续人工联系 | `SuccessState` |
| Mock 会话 | 明确显示演示数据与网络操作限制 | `StatusBanner` |

登录入口页本身没有“空数据”业务状态；不得为了视觉完整性增加空状态。空状态只适用于后续课程、记录或成绩内容页。

## 9. 对应组件名称

| UI 区域 | 现有/建议组件 |
|---|---|
| 背景 | `GridBackground` |
| 学校品牌栏 | `UniversityBrandLockup`、`BrandMark` |
| 登录任务容器 | `SwissPanel` / Material 3 `Card` |
| 卡片标题 | `SectionTitle` |
| 默认登录操作 | `PrimaryActionButton` 或 Material 3 `Button` |
| 次级登录操作 | `SecondaryActionButton`（建议新增）或 `OutlinedButton` |
| 扫码加入课程 | `TertiaryActionButton`（建议新增）或 `FilledTonalButton` |
| Mock 用户 | `DemoActionButton`（建议新增）或 `TextButton` |
| 隐私同意 | `PrivacyConsentRow`（建议新增，支持长文本换行） |
| 隐私政策链接 | `TextButton` / 可访问的 `AnnotatedString` 链接 |
| 分组分隔 | `HorizontalDivider` |
| 账号恢复 | `TextButton` |
| 全局反馈 | `SnackbarHost`、`ErrorState`、`StatusBanner` |

## 10. 不得修改的业务规则

以下规则属于业务和合规边界，本设计规范不得改变：

1. 保留邮箱验证码登录、手机号验证码登录、扫码加入课程、Mock 用户登录和账号恢复五个入口。
2. 现有规则中，所有登录入口的启用状态均受 `privacyAccepted` 控制；未同意隐私政策前不可继续。
3. 应保留应用启动时的会话恢复、认证、隐私确认和未登录状态机。
4. 首次认证后仍须进行正式隐私政策确认、记录版本与时间；不同意则退出登录。
5. `PENDING_CONTACT_BINDING` 用户必须先完成邮箱或手机号绑定，才能使用主功能。
6. 邮箱与手机验证码均保留现有格式校验、六码校验、60 秒冷却和错误码映射。
7. 扫码加入课程在已登录状态可直接提交；未登录状态必须补充姓名、学号、邮箱。
8. Mock 用户保持离线、无 API 客户端、重启后不保留会话的既有行为。
9. 账号恢复仍可在未登录状态发起，并由教师或管理员人工处理。
10. 当前邮箱/手机验证码成功后只返回方法选择页、尚未建立完整 session 的现状不得由 UI 重构擅自改变。

## 11. 验收要点

- 首屏能识别“需要先同意隐私政策，再选择正式登录方式”。
- 用户能在 3 秒内分辨正式登录、扫码加课、Mock 和账号恢复的不同用途。
- 常见小屏、英文文案和系统大字体下，核心操作与隐私文本不被截断、不横向溢出。
- 页面只有一个视觉主标题和一个默认主按钮。
- 本文档中的所有视觉调整均不改变第 10 节业务规则。
